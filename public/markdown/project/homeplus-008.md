#### 개요

**`/commit` — Claude Code / Codex 커밋 메시지 커맨드 가이드**

#### 핵심 요약

`/commit`은 Claude Code 또는 Codex에서 사용할 수 있는 커밋 메시지 자동화 커맨드입니다.

- 스테이징된 변경사항을 분석하여 프로젝트 컨벤션에 맞는 **한글 커밋 메시지 자동 제안**
- 제안된 메시지를 대화형으로 검토 및 수정 가능
- `commit` 또는 `commit + push`까지 연속 실행 가능
- 현재 브랜치명에서 **JIRA Issue Key 자동 추출**
- 변경사항을 기반으로 적절한 `prefix`와 상세 본문 자동 구성

---

#### 1. 무엇인가요?

Claude Code 또는 Codex에서 `/commit`을 입력하면 현재 **스테이징된 변경사항**을 분석하고, 팀의 커밋 컨벤션에 맞춘 `title + body` 형태의 한글 커밋 메시지를 자동으로 제안합니다.

사용자는 제안된 커밋 메시지를 확인한 뒤 다음 작업을 수행할 수 있습니다.

- 메시지 수정 후 다시 제안받기
- 제안된 메시지를 그대로 사용
- 커밋만 실행
- 커밋 후 push까지 연속 실행
- 작업 취소

---

#### 2. 커밋 메시지 형식

#### 기본 템플릿

```text
[JIRA-Issue Key][prefix]: 요약
* 변경한 화면 또는 영역
* 추가 설명
```

#### 예시

```text
[HMP-813][feat]: 상품 상세 리뷰 필터 기능 추가
* 상품 상세 리뷰 영역에 포토 리뷰 필터 추가
* 필터 선택 시 리뷰 목록 조회 조건 적용
```

#### JIRA Issue Key

현재 브랜치명에서 JIRA Issue Key를 자동으로 추출합니다.

예를 들어 브랜치명이 다음과 같다면:

```text
feature/HMP-813-review-filter
```

커밋 메시지에는 다음과 같이 적용됩니다.

```text
[HMP-813][feat]: 리뷰 필터 기능 추가
```

JIRA Issue Key 형식이 확인되지 않는 브랜치라면 **브랜치명 전체를 식별자**로 사용합니다.

#### Prefix 종류

| Prefix     | 용도                                |
| ---------- | ----------------------------------- |
| `feat`     | 새로운 기능 추가                    |
| `add`      | 파일, 설정, 리소스 등의 단순 추가   |
| `fix`      | 버그 수정                           |
| `docs`     | 문서 수정                           |
| `refactor` | 기능 변경 없는 코드 구조 개선       |
| `perf`     | 성능 개선                           |
| `test`     | 테스트 코드 추가 및 수정            |
| `build`    | 빌드 시스템 또는 의존성 변경        |
| `ci`       | CI/CD 설정 변경                     |
| `revert`   | 이전 변경사항 되돌리기              |
| `archive`  | 사용하지 않는 코드 또는 리소스 보관 |

#### 3. 동작 흐름

```text
/commit 실행
    ↓
Git 상태 및 변경사항 분석
    ↓
커밋 메시지 제안
    ↓
메시지 수정 여부 확인
    ↓
실행 방식 선택
    ↓
commit / commit + push
    ↓
결과 출력
```

#### Step 1. Git 상태 분석

`/commit` 실행 시 다음 내용을 자동으로 확인합니다.

- 현재 브랜치
- 스테이징된 파일 목록
- 스테이징된 변경 내용
- 브랜치명에 포함된 JIRA Issue Key

> 커밋 메시지는 **스테이징된 파일만 기준으로 작성**합니다.

---

#### Step 2. 커밋 메시지 제안

분석된 변경사항을 바탕으로 다음 형식의 메시지를 제안합니다.

```text
[JIRA-Issue Key][prefix]: 제목

* 주요 변경사항
* 세부 변경사항
```

---

#### Step 3. 수정 요청

커밋 메시지 제안 후 수정 여부를 확인합니다.

```text
1. 수정
2. 그대로 진행
```

#### `1. 수정`

사용자가 수정하고 싶은 내용을 입력하면 해당 내용을 반영하여 커밋 메시지를 다시 생성합니다.

이후 다시 메시지를 확인합니다.

```text
커밋 메시지 제안
    ↓
수정
    ↓
재제안
    ↓
확인
```

#### `2. 그대로 진행`

현재 제안된 커밋 메시지를 사용하여 다음 단계로 이동합니다.

---

#### Step 4. 실행 방식 선택

커밋 메시지가 확정되면 실행 방식을 선택합니다.

```text
1. 커밋만
2. 커밋 + push
3. 취소
```

#### 1. 커밋만

```bash
git commit
```

까지만 실행합니다.

#### 2. 커밋 + push

```bash
git commit
git push
```

를 연속으로 실행합니다.

#### 3. 취소

커밋을 실행하지 않고 종료합니다.

---

#### Step 5. 결과 출력

실행 이후 결과를 출력합니다.

성공 시:

```text
Commit completed successfully.
```

또는 push까지 진행했다면:

```text
Commit and push completed successfully.
```

오류가 발생하면 Git에서 반환한 오류 내용을 함께 출력합니다.

---

#### 4. 사용 방법

#### Step 1. 변경 파일 스테이징

커밋할 파일만 먼저 스테이징합니다.

특정 파일:

```bash
git add <파일명>
```

전체 변경사항:

```bash
git add .
```

---

#### Step 2. `/commit` 실행

Claude Code 또는 Codex에서 다음 커맨드를 입력합니다.

```text
/commit
```

---

#### Step 3. 커밋 메시지 확인

자동 생성된 커밋 메시지를 확인합니다.

필요하면 수정 내용을 입력하고, 문제가 없다면 그대로 진행합니다.

---

#### Step 4. 실행 방식 선택

```text
1. 커밋만
2. 커밋 + push
3. 취소
```

중 원하는 작업을 선택합니다.

#### 5. 주요 규칙

| 항목           | 규칙                                                               |
| -------------- | ------------------------------------------------------------------ |
| 언어           | 한글                                                               |
| 제목 끝 마침표 | 사용하지 않음                                                      |
| 커밋 목적      | 한 커밋 = 하나의 목적                                              |
| 분석 대상      | 스테이징된 파일만                                                  |
| 제목 표현      | `적용`, `추가`, `제거`, `수정`, `개선`, `정리` 등 명확한 표현 사용 |
| Prefix         | 변경사항을 분석하여 적절한 prefix 선택                             |
| JIRA Key       | 브랜치명에서 자동 추출                                             |
| 본문           | 주요 변경사항과 세부 내용을 요약                                   |

#### 8. Push 사용 시 확인사항

#### 증상

`git commit`은 정상적으로 완료되지만 `push` 단계에서 다음과 같은 인증 관련 오류가 발생할 수 있습니다.

```text
인증 정보가 설정되지 않았습니다.
```

이 경우 `/commit` 스킬의 문제가 아니라 Git Remote 또는 Bitbucket 인증 설정을 확인해야 합니다.

---

#### SSH Key 확인

터미널에서 SSH 키가 존재하는지 확인합니다.

```bash
ls ~/.ssh/
```

출력 결과에서 `.pub` 확장자를 가진 공개키 파일을 확인합니다.

예:

```text
id_ed25519
id_ed25519.pub
```

공개키 내용을 확인합니다.

```bash
cat ~/.ssh/id_ed25519.pub
```

또는 사용 중인 SSH Key 파일명에 맞게 입력합니다.

```bash
cat ~/.ssh/xxxxx.pub
```

---

#### Bitbucket에 SSH Key 등록

Bitbucket에서 다음 메뉴로 이동합니다.

```text
Manage account
    ↓
SSH keys
    ↓
Add key
```

![Manage account](/images/project/manage_account.png)

![SSH keys Add key](/images/project/ssh.png)

터미널에서 확인한 `.pub` 공개키 내용을 등록하면 됩니다.

> `commit + push` 기능을 사용할 예정이라면 `/commit` 사용 전에 Git Remote 인증이 정상적으로 설정되어 있는지 확인하는 것을 권장합니다.
