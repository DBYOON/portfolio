#### 개요

클래스 컴포넌트에 분산된 상태와 라이프사이클 로직을 Hook으로 전환해 유지보수를 쉽게 하고, React 18의 자동 배칭으로 달라진 화면 반영 시점과 라이브러리 호환성 점검

#### 주요 작업

- React 18 변경 사항을 반영한 컴포넌트 구조 개선 참여
- 클래스 라이프사이클을 Hook 기반(useEffect)으로 마이그레이션
- 라이브러리 호환성 점검 및 업그레이드
- React 18 자동 배칭에 따른 UI 상태 흐름 점검 및 즉시 렌더링 대응

#### 개선

| 작업 항목                    | 주요 작업 내용                                                                                               | 작업 결과                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| 클래스 컴포넌트 마이그레이션 | 클래스 라이프사이클을 `useEffect`와 cleanup으로 전환하고, 상태와 인스턴스 변수를 `useState`, `useRef`로 대체 | 부수효과와 생명주기 관리 명확화 및 유지보수성 향상      |
| 라이브러리 호환성 점검       | 주요 UI·상태 관리·테스트 라이브러리의 React 18 지원 여부를 확인하고 업그레이드하거나 문제 컴포넌트를 격리    | 버전 충돌과 ref·렌더링 관련 오류 가능성 감소            |
| 자동 배칭 대응               | 탭·고정 네비게이션·스크롤 UI의 상태 변경과 DOM 측정 순서를 점검하고 필요한 구간에 `flushSync` 적용           | 상태 변경 직후 DOM을 참조하는 UI의 렌더링 타이밍 안정화 |

**React에서 권장하지 않는 flushSync 사용했던 이유**

이벤트(프로모션) 페이지 내에 기획전 상품을 API로 불러오는 과정에서 상품 영역의 높이와 스크롤 좌표가 변경됨.
React 18의 자동 배칭으로 네비게이션 고정(fixed) 상태가 즉시 DOM에 반영되지 않으면 잘못된 좌표를 참조할 수 있어, flushSync로 상태를 즉시 반영한 후 정확한 위치를 계산함.

**flushSync 제거 및 개선 방향**

상품과 이미지 로딩으로 레이아웃이 변경되면 ResizeObserver로 이를 감지하고, useLayoutEffect에서 내비게이션 높이와 스크롤 좌표를 다시 계산합니다. 스크롤 이벤트에서는 미리 계산된 좌표로 fixed 상태와 활성 탭만 변경하도록 분리합니다.
이를 통해 상태 변경 직후 DOM을 강제로 갱신할 필요가 없어져 flushSync를 제거할 수 있으며, 정확한 좌표를 유지하면서 동기 렌더링에 따른 성능 저하도 줄일 수 있습니다.
